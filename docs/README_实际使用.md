# CAXA 图库助手｜实际使用说明 v0.42.13

## 目录结构

- `启动CAXA助手.bat`：唯一日常启动入口。
- `app/`：工作台、悬浮面板、CAD 辅助模块及示例模板。
- `runtime/`：稳定启动器和增量更新器。
- `updates/`：更新源配置、暂存和回滚。
- `docs/`：使用说明和导入模板。
- `logs/`：本机启动与更新日志。

## 首次启动

1. 将完整程序目录解压到固定位置，不要把程序文件与公司 EXB 图纸混放。
2. 双击根目录的 `启动CAXA助手.bat`。
3. 启动器检测 Python 3.10+ 和 Tkinter，再运行悬浮面板。
4. 第一次使用 CAD 控制器时，程序会从 AutoHotkey 官方发布页下载固定版本的便携运行时，并校验 SHA-256。

## 自动更新

安装包已预配置公开 GitHub Raw 更新清单：

`https://raw.githubusercontent.com/y2662151417/caxa-library-helper/main/updates/manifest.json`

每次启动时，程序通过 HTTPS 检查版本和文件 SHA-256，只下载 `app/`、`runtime/` 中发生变化的程序文件。没有变化时不会下载程序文件。下载文件全部通过校验后才替换本机文件；更新失败时记录日志并继续启动原版本。

如果当前网络无法访问 GitHub Raw，自动更新可能暂时无法完成，但不会因此删除本机数据或阻止旧版本启动。检查状态、版本号、下载/替换文件数及失败原因会记录在安装目录的 `logs/launcher.log`。

## 本机数据

图纸扫描记录、SQLite 进度数据库、导入的正式块名称清单、用户模板、模板选择、CAD 控制器运行时和备份保存在：

`%LOCALAPPDATA%\\CAXA_Library_Helper`（如启动配置设置了 `CAXA_HELPER_DATA_DIR`，则以该目录为准）

这些文件不属于公共源码仓库，也不应提交到 Git。增量更新只允许修改 `app/` 和 `runtime/`，不更新用户数据目录、根启动入口或更新源配置。

## 视图模板

在悬浮助手的“设置”中，按当前批次图纸类型选择一次视图模板：

- **三视图**：主视图、俯视图、左视图；每种视图各有带尺寸和无尺寸版本，共 6 项。
- **双视图**：主视图、左视图；每种视图各有带尺寸和无尺寸版本，共 4 项。

模板保存在本机。后续尚未建立视图计划的图纸会自动沿用；已经建立的图纸计划不会因修改默认模板而被覆盖。更换图纸时不再弹出视图选择窗口。右视图、剖视图和局部视图不属于当前默认方案。

## 每张图的基本流程

1. 在图纸管理工作台选择本机 EXB 目录并扫描。
2. 在图纸管理中导入正式块名称 Excel（.xlsx）：第一张可见工作表仅使用 A 列图号、B 列正式块名称。Excel 是正式名称唯一来源，不扫描图库文件夹。
3. 在 CAD 中打开工具创建的工作副本，并连接当前 CAD 窗口。
4. 悬浮助手主按钮直接启动 CAXA 原生 Symdef，并自动输入本张4项或6项视图数量。首次使用时若尚未绑定 CAD，助手会从当前工作副本窗口完成一次连接确认。
5. 在 CAXA 中依次框选每组视图、确认选集并指定该组基点。Symdef 是否按预期连续衔接下一组、全部视图完成后是否自动打开图符入库窗口，仍需 Windows + CAXA 2024 实机确认。正式名称唯一匹配后，在悬浮窗复制名称并由操作者手动粘贴。助手不会自动填写、提交入库或保存。
6. 尺寸层切换、属性填入、图库类别核对、最终入库确认和重新插入检查仍按公司要求完成；确认结果后再记录本张复核状态。

具体 CAD 选集、删除确认、视图框选、基点和最终入库均需操作者检查；离线测试不能替代 Windows + CAXA 2024 实机验收。

## 只读控件诊断

在悬浮面板「更多操作」中点击「只读诊断 CAXA 控件」，选择当前打开的界面阶段。诊断报告保存在用户数据目录的 `diagnostics` 子目录。报告只输出进程名、窗口类名、控件类名和控件位置，不输出窗口标题、控件文字、图纸内容、参数或截图；不发送 CAD 命令、不点击、不修改或保存 EXB。第一轮必须使用自制虚构测试图，不使用公司正式图纸。


## CAXA 配置 Excel（图纸映射 + 颜色规则）

助手使用同一个 .xlsx 文件导入图纸映射和颜色规则。第一张可见工作表中：

**图纸映射表：A-C 列**

| A列 | B列 | C列 |
|---|---|---|
| 图号 | 文件名 | 块名称 |
| CRB01D2084 | CRB01D2084_垂直重锤拉紧装置.exb | CRB01D2084_垂直重锤拉紧装置_B500_08轴_D500 |

每个图号唯一；文件名必须是对应 EXB 文件名；块名称必须以图号加下划线开头。导入时同时核对图号和文件名，避免同图号不同文件错配。

**颜色规则表：建议放在图纸映射表下方，空一行。**

沿用现有 A-E 列，并在 F 列增加“原始颜色”：

| A列：线层 | B列：线型 | C列：线型比例 | D列：线宽 | E列：颜色 | F列：原始颜色 |
|---|---|---:|---|---|---|
| 中心线层 | ByLayer（随层） | 1 | ByLayer（随层） | ByLayer（随层） | 红色 |
| 虚线层 | ByLayer（随层） | 1 | ByLayer（随层） | ByLayer（随层） | 绿色 |
| 双点划线层 | ByLayer（随层） | 1 | ByLayer（随层） | ByLayer（随层） | 蓝色 |
| 细实线层 | ByLayer（随层） | 1 | ByLayer（随层） | ByLayer（随层） | 洋红色 |
| 0层 | ByLayer（随层） | 1 | ByLayer（随层） | ByLayer（随层） | 白色+黑白色 |

当前上传的旧版颜色表没有 F 列“原始颜色”，助手会采用已确认的五组默认映射；如果要在 Excel 中自行维护或调整，按上表补充 F 列和对应行即可。对象颜色、对象线型、线宽均设为 ByLayer，线型比例为 1。

导入一次后，映射保存在本机 SQLite；不需要每次启动助手都重新上传。以后更换规则或增加图纸时，再导入更新后的工作簿。导入失败不会覆盖上一次有效映射。

## 悬浮面板颜色操作状态

主面板直接显示五个颜色按钮（红、绿、蓝、洋红、白+黑）、恢复全选、一键设置特性、删除重线、定义属性块和复制正式块名称。

- 颜色按钮会自动设置 CAXA「拾取过滤设置」对话框中的颜色复选框；白色+黑色同时勾选。CAXA 对话框仍由操作者点击「确定」，之后再框选对象。
- 点击颜色按钮前应先按 Esc 清除旧选集。助手记录本次颜色筛选与当前任务签名；一键设置特性只接受对应的近期筛选流程和非空新选集，避免把旧选集误归到新颜色。
- 一键设置特性不再弹出二次确认。首次使用需在「设置」中校准常用工具栏的图层、颜色、线型、线宽四个下拉框。程序会先核对四个控件及其目标项，再应用 Excel 中的目标图层和 ByLayer 属性。
- 程序还会读取左侧特性栏，要求图层、颜色、线型、线宽和线型比例读回符合目标。线型比例目前只核验是否已等于 Excel 目标值；如果比例不一致，当前版本会停止，不会假称已自动修改。比例字段自动写入待根据实际控件诊断完成。
- 面板显示的是「请求已发送」，不是执行成功；最终结果以 AHK 提示和左侧特性栏读回为准。任何异常都不自动保存 EXB。

设置页中的「诊断左侧特性栏（只读）」用于比例字段排查。先在虚构测试图中框选少量对象，再运行诊断。报告保存在本机数据目录 properties_palette_probe.txt，只包含选集数量、五项属性值和控件类别/ID/位置，不包含图纸文字或几何数据。

拾取过滤窗口诊断报告为 pick_filter_dialog_probe.txt。在悬浮面板设置中点击「打开助手数据文件夹」即可找到。

最终图符属性核对、图库类别确认、入库、重新插入和保存仍由操作者完成。助手不自动提交、不自动保存。
