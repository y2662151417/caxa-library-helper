# GitHub 公共更新源与增量更新

## 更新地址

- 仓库：`https://github.com/y2662151417/caxa-library-helper`
- Manifest：`https://raw.githubusercontent.com/y2662151417/caxa-library-helper/main/updates/manifest.json`
- Base URL：`https://raw.githubusercontent.com/y2662151417/caxa-library-helper/main`

客户端安装包中的 `updates/update_source.json` 已预配置 Manifest 地址。该配置在安装后保存在本机，不由增量更新覆盖。

## 客户端更新规则

1. 启动器通过 HTTPS GET 读取公开 `manifest.json`。
2. 校验应用 ID、版本号、文件路径、大小和 SHA-256。
3. 只允许更新 `app/`、`runtime/` 下的文件；不接受绝对路径、`..`、符号链接、非 HTTPS 或跨主机下载地址。
4. 所有变更文件先下载到暂存区并完成哈希校验。
5. 替换前备份旧文件；全部成功后写入版本号。
6. 任一步骤失败则回滚，启动器继续启动旧版本。

## 本机数据隔离

用户数据位于 `%LOCALAPPDATA%\CAXA_Library_Helper`。更新器的允许路径只有 `app/` 和 `runtime/`，因此不能覆盖 EXB、工作副本、SQLite 进度库、正式块名称清单、用户模板、备份或日志。

## 发布新版本

在本地仓库根目录完成程序修改并更新 `app/VERSION.txt`，然后运行：

```bash
python devtools/release/build_update_feed.py \
  --install-root . \
  --version 0.40.0 \
  --output ./build/update-feed \
  --base-url "https://raw.githubusercontent.com/y2662151417/caxa-library-helper/main"
```

脚本在 `build/update-feed/` 生成新版本 `app/`、`runtime/` 文件树和 `manifest.json`。将程序变更提交到仓库根目录的 `app/`、`runtime/`，并将生成的 `manifest.json` 放入仓库 `updates/manifest.json`，再一起推送到 `main`。客户端下次启动时只下载 SHA-256 发生变化的程序文件。

不要把 `build/update-feed/` 整个目录复制到根目录；不要提交本机 `data/`、`config/`、`logs/`、`backups/`、EXB 或数据库。
