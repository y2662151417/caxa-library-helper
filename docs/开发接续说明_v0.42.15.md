## 本轮实机问题与代码层根因

用户在 CAXA 2024 中点击“绿色”后：
- 悬浮窗显示已发送绿色筛选请求；
- AHK 弹出“面板请求已过期；请重新点击操作按钮”；
- CAXA 的拾取过滤设置仍然保持红、黄、绿、青、蓝、洋红、白、黑全部勾选。

核对旧分支与 v0.42.15 代码后发现一个明确的版本识别缺陷：
- v0.42.14 的 AHK 控制器使用本地时间 DateDiff 和 30 秒请求 TTL。
- v0.42.15 的 Python 面板只检查 ahk_controller.pid 对应进程是否存活，不检查该进程实际运行的是哪个 AHK 脚本版本。
- 用户切换 Git 分支并重启 Python 面板时，Windows 中先前启动的旧 AHK 进程仍可能存活；面板会误判为“控制器已连接”，并把新请求写给旧控制器。
- 因此，截图中的过期提示高度符合“新 Python 面板 + 旧 AHK 控制器”版本错配。尚未读取用户本机日志，不能声称已对该次进程身份做实机证明。

## v0.42.16 本轮修改

1. Python 写入 panel_action.ini 时，created_at 改为 10 位整数 Unix epoch 秒，避免浮点文本解析差异。
2. AHK 只接受 10 位 epoch 秒，并用 A_NowUTC 计算请求年龄；队列 TTL 保持 300 秒。
3. AHK 启动时同时写入：
   - ahk_controller.pid
   - ahk_controller_build.txt
   构建标识为 caxa-helper-v0.42.16。
4. AHK 正常退出时，在 PID 仍匹配的前提下清理两个标记。
5. Python 控制器启动等待必须同时匹配 PID 和 build ID。
6. 悬浮窗启动检查和每次发送操作前都检查 build ID。发现旧控制器时禁止发出 CAD 操作请求，并提示退出托盘旧版 H 图标、重新启动助手。
7. 保留任务签名、工作副本身份和 35 秒实时工作台租约；没有为消除过期提示而取消安全校验。

## 用户确认的功能要求（保持不变）

### 颜色筛选
- 红色 → 中心线层
- 绿色 → 虚线层
- 蓝色 → 双点划线层
- 洋红色 → 细实线层
- 白色+黑白色 → 0层
- 面板五个直接颜色按钮，另有恢复全选。
- 点击按钮后自动设置 CAXA 拾取过滤对话框颜色复选框；白色与黑色同时勾选。
- 不改变实体类型、尺寸、图层、线型筛选条件。
- 用户自行点击 CAXA 对话框“确定”，之后框选对象。

### 一键设置特性
- 不弹二次确认。
- 按 Excel 规则设置目标图层、对象颜色 ByLayer、对象线型 ByLayer、线型比例 1、对象线宽 ByLayer。
- 执行后以左侧 CAXA 特性栏读回核对。
- 不自动保存 EXB、不自动提交图库、不自动入库。

## 已有功能边界（不可误报）

- 五色按钮和 AHK 自动勾选逻辑已写入 v0.42.15；本轮主要修复控制器版本错配和请求时间戳，不代表已经通过 CAXA 2024 实机验证。

## 用户下一次测试步骤

1. 在 GitHub Desktop 点击 Fetch，切换到 work/v0.42.16-controller-handshake；不要合并 main。
2. 退出旧的 CAXA 制作助手面板。
3. 在 Windows 系统托盘右下角找到旧版 AutoHotkey 的绿色 H 图标，右键选择 Exit。若有多个由本助手启动的旧 H 图标，逐一退出；不要退出其他用途的 AHK 脚本。
4. 从当前仓库重新启动助手。等待状态显示控制器已连接，并带有 v0.42.16 构建标识。
5. 打开虚构 EXB 工作副本，按 Esc 清空选集，再点击“绿色”。
6. 预期：CAXA 拾取过滤窗口只勾选绿色，其他颜色取消。用户自行点击“确定”。
7. 再分别测试红色、蓝色、洋红色、白色+黑色和恢复全选。
8. 颜色筛选通过后，再用少量测试对象验证一键设置特性；检查左侧特性栏，不要在生产图纸首次测试。

若仍出现“请求过期”或“控制器版本不匹配”，请从助手数据文件夹发回：
- panel_action_expiry.log
- ahk_controller_startup.log
- ahk_controller_marker_error.log（若存在）
- ahk_controller.pid 与 ahk_controller_build.txt（文本内容即可）
