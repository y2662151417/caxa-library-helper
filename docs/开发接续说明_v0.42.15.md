## 用户已确认的目标

### 颜色筛选
五个直接按钮：红色、绿色、蓝色、洋红色、白色+黑白色；另一个按钮恢复全选。颜色规则：
- 红色 → 中心线层
- 绿色 → 虚线层
- 蓝色 → 双点划线层
- 洋红色 → 细实线层
- 白色+黑白色 → 0层

点击颜色按钮应自动设置 CAXA 拾取过滤窗口中的颜色复选框；不应让用户逐项手动勾选。白色和黑色同时勾选。CAXA 过滤窗口仍由用户点击“确定”，之后用户框选对象。

### 一键设置特性
不弹出二次确认。按 Excel 映射设置：
- 目标图层：按源颜色映射
- 对象颜色：ByLayer
- 对象线型：ByLayer
- 线型比例：1
- 对象线宽：ByLayer

属性修改后以 CAXA 左侧特性栏为读回依据。助手不自动保存 EXB、不自动提交图库、不自动入库。

## 本轮代码状态

### 已实现
- 面板首页五个颜色按钮 + 恢复全选。
- AHK 自动定位“拾取过滤设置”窗口并只操作颜色分组。
- 自动取消其他颜色，再勾选目标颜色；白+黑为双勾选。
- 对标准颜色组逐项读取状态；不确定时停止。
- 点击颜色按钮前要求旧选集为空；一键设置必须与最近的颜色筛选和当前任务签名匹配。
- 属性操作不弹二次确认；Excel 规则中的图层、颜色、线型、线宽进入已校准的四个 CAXA 常用属性工具栏下拉框。
- 属性栏读回检查，工具栏自身显示值不再作为成功唯一依据。
- 新增左侧特性栏只读诊断，文件名 properties_palette_probe.txt。
- 面板请求使用 created_at Unix epoch + AHK A_NowUTC，300 秒队列 TTL；活动任务签名与实时工作台租约仍保留。
- 修复 findPickFilterDialog 在 100ms 等待循环内重复执行昂贵 verifyBeforeAction 的问题，避免反复启动 Python 哈希/SQLite 预检。
- 过期请求诊断日志 panel_action_expiry.log 不包含图纸名称或任务签名。

### 明确未完成/不能宣称完成
1. 颜色按钮自动勾选尚未在用户 CAXA 2024 实机验证。若 CAXA 复选框控件不是可读写的标准 Button，代码会停止并生成 pick_filter_dialog_probe.txt。
2. 四个工具栏 ComboBox 尚未实机确认确实修改了当前选集对象。首次使用要校准一次；应用后必须看左侧特性栏。
3. 线型比例自动写入尚未实现。本版只读取当前比例；若当前比例与 Excel 不同，则在改其他属性前停止。不要把“线型比例已经核验”说成“已经自动设置”。
4. 左侧属性栏诊断尚未由用户运行；需用户发回 properties_palette_probe.txt 后再决定比例字段的安全写入方式。
5. Windows AHK 语法检查和 Python CI 尚待新 PR 验证；CI 通过也不代表 CAXA 实机通过。

## 用户测试步骤（仅虚构工作副本）

1. 在 GitHub Desktop 切换到 work/v0.42.15-direct-color-actions，先不要合并 main。
2. 打开虚构测试 EXB，发布/核对当前工作副本，连接 CAXA。
3. 按 Esc 清除已有选集。
4. 点击“绿色”；预期拾取过滤窗口颜色列表只有绿色勾选。检查后由用户点击“确定”。
5. 框选少量测试对象；在设置中一次性校准图层、颜色、线型、线宽四个工具栏下拉框。
6. 点击“一键设置特性”；检查左侧特性栏的图层、颜色、线型、线宽。线型比例应为 1；如果不是，当前版本会拒绝执行其他属性修改。
7. 选中少量测试对象后，在设置中点击“诊断左侧特性栏（只读）”，将助手数据目录中的 properties_palette_probe.txt 发回。
8. 分别测试红、蓝、洋红、白+黑和恢复全选；不要使用真实生产图纸做首次测试。

## 安全边界

- 任务签名、当前工作副本身份、实时租约必须保留。
- 过滤只改颜色列表；不改实体类型、尺寸、图层和线型筛选。
- 属性写入只作用于当前 CAXA 选集；执行前检查选集非空，执行后核对数量与左侧特性栏。
- 不自动选择图元、不自动点击最终图库入库、不自动提交、不自动保存 EXB。
